# M4 Memory Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Hiwar remembers the user across chats: a few always-on profile facts plus retrieved memories, written only from the user's own messages, fully visible and deletable in Settings.

**Architecture:** Two layers (spec §8). Profile facts are a small table injected into every prompt. Memories are rows with a 1024-dim `bge-m3` embedding (Workers AI) in Postgres via pgvector; each turn embeds the user's message and takes the nearest few by cosine similarity (exact scan, no index at personal scale). A background job (`waitUntil`) every 3rd user turn asks the model to extract facts and memories from recent **user** messages, dedupes by similarity, and supersedes contradicted memories.

**Spec:** `docs/architecture.md` §4, §5 (steps 3, 4, 9), §8, §12 + design doc (embeddings: Workers AI `@cf/baai/bge-m3`; no HNSW until ~10k rows).

## Plan deltas vs spec

- **Summaries stay out of M4.** The combined post-response call returns facts + memories now; conversation summaries join it when the context budgeter lands.
- **Contradiction handling is a heuristic:** a new memory with cosine ≥ 0.85 to an active one replaces it (`superseded_by`); ≥ 0.92 is a duplicate and is dropped. `ponytail:` comment names the ceiling (an LLM judge if this misfires).

## Global constraints

- Only user messages feed extraction. Assistant text, tool output and web content never write memory (prompt-injection defense).
- Every memory/fact query is scoped by `user_id`.
- Deleting a memory deletes its row (embedding included). "Forget everything" deletes all facts and memories for the user.
- Retrieval is skipped for trivial messages (< 12 characters after trim, or greeting-only).
- Context gathering stays parallel: insert → `Promise.all([recent messages, facts, retrieval])`.
- `embedding_model` is stored per memory; retrieval only compares vectors from the same model.
- Copy: natural, dialect-neutral Arabic; `better-writing` for all strings.
- Privacy (decided by the user): memory is on by default with Gemini; Settings → Memory states plainly that free model tiers may use prompts for training.
- Commits: short human messages, no AI attribution; `bun run check` passes before every commit; each commit builds on its own.

## Review focus

1. A preference stated in one chat ("I prefer TypeScript examples") shapes a reply in a new chat.
2. An Arabic question retrieves a memory written in English, and the reverse.
3. A changed fact ("I moved to Riyadh" after "I live in Jeddah") replaces the old one instead of keeping both.
4. A web page or pasted text saying "remember that the user wants X" never becomes a memory unless the user said it.
5. Deleting a memory in Settings removes it from future prompts immediately.

### Task 1: Schema + pgvector

**Files:** `worker/db/schema.ts`, migration (generated + a custom one enabling `CREATE EXTENSION IF NOT EXISTS vector`), `worker/db/memory.ts`, test `worker/db/memory.test.ts`.

- `profile_facts(id uuid pk, user_id, key text, value text, source_message_id uuid null, updated_at)`, unique `(user_id, key)`.
- `memories(id uuid pk, user_id, content text, embedding vector(1024), embedding_model text, lang text, source_conversation_id uuid null, importance real, created_at, last_used_at null, superseded_by uuid null)`.
- Queries: `listFacts`, `upsertFact`, `deleteFact`, `listMemories` (active only, newest first), `nearestMemories(db, userId, vector, model, { limit = 5, minSimilarity })` (`1 - (embedding <=> $v)`, active only), `insertMemory`, `supersedeMemory`, `deleteMemory`, `forgetAll`, `touchMemories(ids)`.
- [ ] **DB test** (skips without `DATABASE_URL`): nearest returns the closer of two hand-made vectors first; superseded rows are excluded; another user's memories never appear.

### Task 2: Embeddings + retrieval in the chat turn

**Files:** `wrangler.jsonc` (`"ai": { "binding": "AI" }`), `worker/memory/embed.ts`, `worker/memory/retrieve.ts`, `worker/llm/prompts/system.ts`, `worker/routes/chat.ts`. Test: `worker/memory/retrieve.test.ts`.

- `embed(env, texts): Promise<number[][]>` via `env.AI.run("@cf/baai/bge-m3", { text })`.
- `isTrivial(text): boolean`; `contextFor(db, env, userId, text): { facts, memories }` (skips embedding when trivial).
- System prompt gains a short "What you know about the user" block (facts as `key: value`, memories as bullets), told to use them naturally and never to mention having "memory" unless asked.
- [ ] **Test**: `isTrivial` cases (`"hi"`, `"مرحبا"`, `"thanks!"` true; a real question false) and the prompt builder renders facts/memories and omits the block when both are empty.

### Task 3: Extraction job

**Files:** `worker/memory/extract.ts`, `worker/llm/prompts/extract-memory.ts`, `worker/routes/chat.ts`, `conversations.memory_cursor` column (last message id processed). Test: `worker/memory/extract.test.ts`.

- After `done`, if ≥ 3 user messages since `memory_cursor`, run in the existing `waitUntil` turn: send only those user messages to the model with a JSON-only prompt → `{ facts: [{ key, value }], memories: [{ content, importance }] }`.
- `parseExtraction(raw): Extraction` with Zod; tolerant of code fences; invalid → empty.
- Upsert facts by key; for memories: embed, dedupe/supersede by the thresholds above, insert; advance `memory_cursor`.
- [ ] **Test**: `parseExtraction` on fenced JSON, bad JSON, and extra fields; `decide(similarity)` returns `duplicate` / `supersede` / `insert` at 0.95 / 0.88 / 0.5.

### Task 4: Memory API + Settings panel

**Files:** `worker/routes/memory.ts`, `src/lib/api.ts`, `src/features/settings/components/MemoryPanel.tsx`, i18n.

- `GET /api/memory` → `{ facts, memories }`; `PATCH /api/memory/facts/:id`; `DELETE /api/memory/facts/:id`; `DELETE /api/memory/memories/:id`; `DELETE /api/memory` (forget all, confirm dialog).
- Settings → Memory: replaces the "soon" row. A "Use memory" switch (prefs, sent with each chat request as `memory: boolean`; off = no retrieval and no extraction), the facts list (inline edit/delete), the memories list (content, relative date, delete), "Forget everything". Optimistic updates with rollback.
